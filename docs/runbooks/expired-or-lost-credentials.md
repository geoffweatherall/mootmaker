# Expired or lost credentials

The system has very few long-lived credentials. This runbook covers each one: what breaks when it expires
or is lost, and how to replace it.

## RELEASE_TAG_PAT

A fine-grained GitHub personal access token, stored as a secret in mootmaker-release. The release's `tag`
job uses it to push `vX.Y.Z` tags to the repositories it releases. Fine-grained tokens expire (at most a
year after creation), so this **will** fail one day.

**Symptom**: a release fails at `tag` with `401`, `403`, `Bad credentials` or "Resource not accessible".
Nothing has been deployed. The builds' version number is used up; the next release takes the next one.

**Replace it**:

1. GitHub → Settings → Developer settings → Fine-grained personal access tokens → Generate new token.
2. Resource owner `geoffweatherall`; repository access **only** mootmaker-api, mootmaker-webapp,
   mootmaker-demo-data, mootmaker-android and mootmaker-release.
3. Permissions: **Contents: Read and write**. Nothing else.
4. Set an expiry and put a reminder in the calendar a week before it.
5. Store it without echoing it anywhere:

   ```bash
   gh secret set RELEASE_TAG_PAT -R geoffweatherall/mootmaker-release    # paste when prompted
   ```

6. Revoke the old token, and release again with `bump=patch`.

The token's value must never pass through a terminal transcript or an AI session.

## The Android signing key

The release keystore signs every APK. Android only installs an update signed with the same key as the
installed app. It is stored as four secrets in mootmaker-release (`ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) and backed up offline by Geoff.

| Situation | Effect | What to do |
|---|---|---|
| The secrets were deleted, backup intact | Releases skip every Android stage (a notice says so) and publish no APK | Restore the four secrets from the backup |
| The key is lost entirely | No update can ever be installed over existing installs | Generate a new key and set the secrets. Every user must uninstall and reinstall. Say so in the release notes |
| The key leaked | Someone else can sign APKs that phones accept as updates | Generate a new key, set the secrets, publish a release, and tell users to uninstall and install it fresh. Treat it as a [security incident](security-incident.md) |

## npm publishing

The schema is published by trusted publishing (OIDC), so there is no npm token to expire. If
`publish-schema.yml` starts failing with an authentication error, check on npmjs.com that the package's
trusted publisher still names `geoffweatherall/mootmaker-api` and `publish-schema.yml`.

## Machine-client secrets

The Cognito machine clients' secrets (for tests and demo-data) are generated by Terraform and stored in
SSM. They do not expire. To rotate one, replace the client in mootmaker-api's Terraform (for example with
`terraform apply -replace=aws_cognito_user_pool_client.demo_data`) and release.
